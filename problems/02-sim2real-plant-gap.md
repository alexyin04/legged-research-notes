# 问题 2：sim2real 的差距到底从哪来

> 最后更新：2026-10

## 一句话

**"仿真里能跑、上真机就抖"这个差距里，物理参数、执行器模型、接触模型各占多少？**

换成可操作的问法：把策略从训练器搬到另一个仿真器，**只对齐物理参数**能不能复现原行为？
如果不能，剩下的是哪一块？

## 现在最好做到什么

以下是我自己量的。做法是：把 IsaacGym 训练出来的策略搬到 MuJoCo，
**先按配置文件标称值搭模型**，然后逐项对齐，看行为差多少。

### 第一层：物理参数对齐

| 参数 | 训练时**实际值** | 配置文件**标称值** |
| --- | --- | --- |
| **关节阻尼** | **1.088** | 0 |
| 地面摩擦 | **0.633** | 1.0 |
| 机身附加质量 | −0.593 kg | 0 |
| armature | 0.005 | 0 |
| 关节摩擦 | 0.0209 | 0 |
| 质心偏移 | [−0.021, −0.024, −0.019] m | 0 |
| 控制延迟 | 子步 1（5 ms） | 无 |

**对齐前后的行为差**（同一策略、同一指令 0.5 m/s）：

| 指标 | 按标称值 | 对齐后 |
| --- | --- | --- |
| 打滑（m/s） | 0.808 | **0.086** |
| 机身高度标准差 | 0.0316 | **0.0037** |
| 速度跟踪（指令 0.5） | 0.213 | **0.481** |

**最关键的是关节阻尼。** 标称值 0 意味着腿完全欠阻尼——
脚在地面上打颤蹭地，步态从"走"变成"抖"。

> ⚠️ 为什么会有这个差距：训练时关掉 `push_robots` **不等于**关掉了整个 domain randomization。
> 其余随机化在播放时仍然生效，你在 sim2sim 里看到的物理是"随机化后的那一个实例"。
> **正确的做法是从训练环境里把真实参数 dump 出来，而不是读配置文件。**

### 第二层：执行器理想化

训练里的电机是**理想力矩源**：要多少给多少，没有转速上限，没有电流环。

实测下来，换成真硬件后最紧的不是扭矩，是**转速**：

- 策略对 calf 的最大扭矩索求 48 Nm，硬件有 93.9 Nm —— **扭矩是没人用的余量**
- 但仿真峰值转速 18.5–19.5 rad/s，硬件只有 16.6 rad/s，而**仿真器不强制转速上限**

### 第三层：接触与冲击

策略落地前一瞬间会**主动蹬地**：触地前 40 ms，腿的下降速度是自由落体的 1.62 倍，
冲击动能 **2.61 倍**。

而**扫接触参数完全改不了这一点**（`solref` 从 0.02 调到 0.004、`margin` 从 0.01 调到 0，
冲击速度不变）。说明这是**策略行为**，不是仿真 artefact。

## 主要路线

1. **域随机化覆盖** —— 核心假设：只要训练时随机得够宽，真实参数一定落在分布内。
   代价是策略会变得保守。
2. **系统辨识（sysid）** —— 核心假设：真机参数可以测出来，直接对齐仿真。
   代价是需要专门的辨识实验，且参数会随温度、磨损漂移。
3. **执行器建模** —— 核心假设：sim2real 的主要残差在电机，不在刚体。
   加力矩-转速曲线、电流限幅、电流环一阶低通。

## 卡在哪

- **"配置里写的"和"实际跑的"不是一回事。** 域随机化在播放时仍然生效，
  但**没有任何机制告诉你"这次播放用的是哪组参数"**。这是工程上的可观测性缺口。
- **执行器模型普遍是理想的。** 大多数开源训练框架里的电机就是
  `effort = kp·err + kd·err_dot` 再加限幅，没有转速-扭矩包络、没有电流动态。
  这是和产品级仿真最大的差距。
- **接触参数没人标定。** 地面刚度、阻尼、摩擦锥基本靠拍。而落地冲击恰恰是接触模型最敏感的地方。
- **没有统一的"sim2real 保真度"指标。** 每个人都说自己的模型"够准"，但没有可比的标准。

## 我怎么想

**我认为**这三层的贡献排序是：**参数可见性 > 执行器模型 > 接触模型**。

理由：

1. **参数可见性**的修复成本最低、收益最大（一次 dump 就解决，行为差一个数量级）。
   它不是"建模精度"问题，是"你到底在跑什么"的问题。
2. **执行器模型**是剩余差距的主体。参数对齐之后行为已经能复现大部分；
   剩下的偏差集中在高动态动作（落地、急停），而那正是电机最容易饱和的地方。
3. **接触模型可能没有大家想的那么重要**。证据：扫接触参数对落地冲击完全没有影响，
   说明在这个场景里冲击是由策略决定的，不是由接触模型决定的。

**如果我错了**，会是因为：我的接触参数扫描范围不够宽，或者我用的地形太"友好"，
换成软地面 / 沙地之后接触模型会变成主因。

## 我能怎么测

| 要验的东西 | 怎么测 | 看什么信号 |
| --- | --- | --- |
| 参数可见性的影响 | 单参数消融：只改阻尼，其余固定，扫 0 → 1.088 | 行为指标随参数的变化曲线，找拐点 |
| 旋钮到底有没有生效 | 同一套测试跑两次，只改一个环境变量，**diff 两份 JSON** | 一模一样 = 那个旋钮是死的（我在这上面白跑过 7 轮 A/B） |
| 执行器的真实约束 | 记录策略索求的扭矩-转速轨迹，画到硬件包络图上 | 有多少工作点落在包络外 |
| 延迟的影响 | 注入 0 / 5 / 10 / 20 ms 恒定延迟与抖动 | 速度、偏航摆动、摔倒率 |
