# 改进历程

这个项目从能站到能走，中间改了十次。每一版改了什么、为什么改，记在下面的表里。
详细版见主仓库的 [CHANGELOG.md](https://github.com/alexyin04/dreamwaq-quadruped/blob/main/CHANGELOG.md)。

## 版本链

| 版本 | 做了什么 | 为什么 |
| --- | --- | --- |
| v0 | 平地起步 | 从 LeggedGym-Ex 的 go2_dreamwaq 移植，先让策略在平地上学会走 |
| v1 | 加地形 | 平地太简单，加 rough curriculum 让策略接触台阶和坡 |
| v2 | PD 增益 + DR | PD 增益 50/80/90 改成 40/40/80；域随机化对齐 go2 |
| v3 | 打开指令课程 | 让指令范围逐步扩大，不要一开始就要求高速 |
| v5 | 回到 v0 重开 | v3 之后没走通，推倒重来 |
| v6 | 照搬 go2 | 把 go2 的参数全部拿过来试 |
| v7 | 关节轴归一化 | URDF 里混了四种轴向约定，统一了 |
| v8 | 收窄指令范围 | 指令上限收到机器人实际能跑到的 0.9 m/s |
| v9 | 执行延迟建模 | 延迟按仿真子步做，0/5/10 ms，均值 5 ms，对应实测 3–10 ms |

## 几个观察

**v5 是推倒重来。** v1→v2→v3 走到一半没走通，v5 回到 v0 重新开始。
这比一条直线更能说明问题：有时候不是参数没调好，是方向错了。

**v7 的轴归一化是最关键的一步。** URDF 里 FL/RL 的 thigh+calf 用了 (0,-1,0)，
其他用 (0,1,0)，混了四种约定。统一之后策略才正常。

**v9 的延迟建模是最后的临门一脚。** 原来的延迟模型只能表达 {0, 20} ms，
太粗。改成子步粒度后能表达 0/5/10 ms，更接近真实。

## 一个反直觉的发现

训练过程中的能力不是单调变强的。v9 的 5 个 checkpoint 跑同一套测试：

| 迭代 | 通过 |
| --- | --- |
| 4500 | 25/45 |
| 4750 | 28/45 |
| 5000 | 25/45 |
| 5250 | 28/45 |
| 5500 | 28/45 |

通过数在 25 和 28 之间来回。有些地形后期才突破，有些地形中途退化后再也没回来。
详细数据见 CHANGELOG 附录。
