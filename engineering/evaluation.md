# 泛化性怎么测：一套可复现的测试体系

> 大多数 locomotion 论文的评测方式是"在 N 种地形上的成功率"。
>
> 这套体系想解决三个具体问题：**"原地不动"不会摔**、**"成功"没有定义**、**结果不可比**。

---

## 一、先说说"成功率"为什么会骗人

假设一个策略在台阶测试上"成功率 100%"。

它可能是真的能上台阶，也可能是：**它在台阶前面原地踏步直到超时，从来没有摔倒过。**

"没摔"是一个**比"做到"弱得多**的指标。用它当主指标，会系统性地高估策略。

所以这套体系的第一个决定是：**主指标用"通过距离"和"进度百分比"，而不是"摔没摔"。**

第二阶段再补上分项指标（打滑、速度跟踪误差、姿态标准差、峰值扭矩）。

---

## 二、七个维度，123 个用例

泛化性不是一个数，是七个正交的方向。每个方向单独测，才能定位"弱在哪"。

| 维度 | 测什么 | 典型用例 |
| --- | --- | --- |
| **指令范围** | 速度指令超出训练分布还能不能跟 | 0.2–1.2 m/s 扫描，含侧向与偏航指令 |
| **物理参数** | 质量和摩擦变了会不会崩 | 负载 0/5 kg、地面摩擦 0.3–1.0 |
| **地形** | 离散障碍的通过能力 | 45 种：台阶 / 沟壑 / 碎石 / 轮胎阵 / 斜坡 / 坑洞 |
| **扰动** | 外力与冲击 | 侧向 50/100 N 持续力、冲量 |
| **初始状态** | 非理想起步 | 初始高度 / 姿态偏差 |
| **执行器故障** | 单关节锁死能不能跛行 | 锁髋 / 锁膝 |
| **传感器退化** | 姿态估计误差与噪声 | 重力零偏 0.05–0.30、噪声、延迟 |

**为什么这七维要分开**：合在一起只看总分，你只知道"不行"，不知道"哪不行"。

---

## 三、45 种地形是怎么设计的

地形库不是随便撒点噪声，是**按"障碍的形态维度"枚举**：

- **垂直方向**：上台阶 / 下台阶 / 高台 / 沟壑（单级 vs 多级）
- **水平方向**：坑洞（无底坑 vs 有底坑）
- **连续高频**：碎石阵（幅值扫描）、轮胎阵
- **连续斜坡**：上坡 / 下坡 / 侧向斜坡（角度扫描）

每一类都做成**参数化生成器**，角度的粒度是 5°，高度的粒度是 5 cm —— 这样"在哪一档断崖"就看得见。

**关键设计：每个地形都是"可判定通过与否"的。**
从起点到终点有明确距离，跑到终点算通过，跑出去或超时算失败，摔倒记录摔倒时刻。

---

## 四、两个容易做错的地方

### 1. 判摔必须用"相对脚下地面"的高度

用世界坐标的绝对高度判摔，**所有下行地形都会误判**：
下坡走 5 m，地面已经降到 −0.87 m，正常走路会被判成摔倒。

正确做法：从机器人向下打射线，取**脚下局部地面**的高度作基准。
单点射线不够——相邻地形瓦片共享面，射线会从缝里漏过去，所以要**5 点十字采样取最高**，并让瓦片重叠 2%。

### 2. 通过距离的标定基线不能太短

如果基线只有 1 m，那么"卡在起点、原地晃了两下走了 1.08 m"会显示 100% 通过。

基线要设成"合格策略应该轻松跑完"的距离，让**卡住**和**通过**在数值上分得开。

---

## 五、结果要能对比

每次测试输出一份 JSON，包含：

```json
{
  "tag": "v9_terrain",
  "policy": "policy_v9_5500.npz",
  "plant": { "关节阻尼": 1.088, "地面摩擦": 0.633, "...": "..." },
  "cases": [
    { "name": "step_up:20", "fell_at": null, "reach_frac": 0.27, "distance_m": 1.08 }
  ]
}
```

配套一个对比脚本：**新增摔倒会单独列在最前面**，其次是进度退化超过 5% 的条目。

⚠️ 这里有个坑：对比脚本如果只认 `fell` 字段，就会漏掉 `fell_at`（地形套件的字段名），
而且**进度从来不会被监视**——一条地形从"走 6 m"退化成"卡在 1 m"会被报成"没有变化"。

---

## 六、这套体系能回答什么

有了这七个维度和参数化的地形库，下面这些问题就变成**可以量化回答**的：

- 换一个执行器（扭矩更大但转速更慢），通过率会怎么变？
- 换个物理参数（阻尼 / 摩擦），曲线是平移还是变形？
- 某一类地形失败，是信息不够（看不到）还是能力不够（做不到）？
- 训练分布加一项，哪一维改善、哪一维反而退化？

**这套东西的价值不在于"跑了个测试"，而在于它把"策略行不行"从一句主观判断变成了曲线。**
